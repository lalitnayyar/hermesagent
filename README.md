# Hermes AgentFlow Studio

A modern, responsive web application for the **Hermes AgentFlow Studio** multi-agent orchestration platform. It provides a React/TypeScript frontend, FastAPI backend, SQLite data store, and Docker orchestration for both AgentFlow and the Hermes agent/gateway.

## Tech Stack

- Vite + React 18 + TypeScript
- Tailwind CSS with custom design tokens
- React Router
- Zustand (global state + `localStorage` persistence)
- @xyflow/react (workflow designer)
- Recharts (monitoring charts)
- vite-plugin-pwa
- FastAPI + SQLAlchemy (backend)
- Docker Compose

## Features

- **Dashboard** — live fleet stats, recent running tasks, and agent fleet cards.
- **Agents** — create, edit, delete, run, and pause agents.
- **Workflows** — visual React Flow canvas with drag-and-drop blocks, conditional
  diamond nodes, Tool/Output blocks, test-run, save, publish, and delete.
- **Tasks** — create, run/pause/resume/retry/delete tasks with auto-simulated
  progress.
- **Approvals** — approve/reject requests and view the decision log.
- **Automation** — trigger workflows that create tasks and toggle scheduled runs.
- **Monitor** — live throughput chart, service health toggle, and activity feed.
- **Mobile** — mobile companion for approvals, active tasks, and quick actions.
- **Chat Test** — test `Send to Hermes` and `Ask Ollama` from the UI.
- **Settings** — persisted Hermes API/Gateway, Ollama host, limits, and
  governance toggles, each with a **Test** button for reachability/response.
- **Activity Logs** (`/logs`) — filtered, chronological list of all application
  events.

## Hermes & Ollama Networking

- AgentFlow backend runs inside Docker.
- Hermes API in Docker is reachable at `http://hermes-agent:8642`.
- Hermes dashboard/gateway in Docker is reachable at `http://hermes-agent:9119`.
- Ollama on the **host** is reachable from Docker via `http://host.docker.internal:11434`.
- Ollama must bind to `0.0.0.0` to be reachable from Docker:

  ```bash
  OLLAMA_HOST=0.0.0.0:11434 ollama serve
  ```

- Localhost (`127.0.0.1`, `localhost`) URLs entered in Chat Test/Settings are
  automatically translated to the correct Docker hostnames by the backend.

## User Guide

1. Copy the environment file:

   ```bash
   cp .env.example .env
   ```

2. Fill in `.env`, especially:

   - `HERMES_API_SERVER_KEY` — if your Hermes API is key-protected.
   - `HERMES_NETWORK` — Docker network that contains Hermes Agent and Workspace.

3. Start Hermes:

   ```bash
   ./manage.sh start-hermes
   ```

4. Start Ollama on all interfaces (optional, for local model chat):

   ```bash
   OLLAMA_HOST=0.0.0.0:11434 ollama serve
   ```

5. Start AgentFlow:

   ```bash
   ./manage.sh start
   # or with full rebuild:
   docker compose -f docker-compose.yml up -d --build
   ```

6. Open the UI:

   ```text
   http://127.0.0.1:3080
   ```

7. Verify the backend:

   ```bash
   curl http://127.0.0.1:3080/api/health
   ```

## Management Scripts

- `manage.sh` — start/stop/deploy AgentFlow and Hermes, view logs, backups, etc.
- `manage-containers.sh` — interactive menu to start, stop, rebuild, and view
  logs for **all** containers (AgentFlow + Hermes).

```bash
./manage-containers.sh
```

## Troubleshooting

- **Hermes `api_server` cannot bind 127.0.0.1:8642** — another process is
  already using port 8642. Stop it, or change the Hermes `config.yaml`
  `platforms.api_server.port` and restart with `./manage.sh stop-hermes` then
  `./manage.sh start-hermes`.

- **Ollama `Connection refused` from the Chat Test** — Ollama is either not
  running or only bound to `127.0.0.1`. Start it with
  `OLLAMA_HOST=0.0.0.0:11434`.

- **Hermes chat returns the sign-in page (200)** — `Send to Hermes` is posting
  to the dashboard. Make sure `HERMES_API_SERVER_KEY` is set in `.env` and
  restart the backend container.

## Notes

- Application state is persisted to `localStorage` in the browser; a `version`
  migration keeps URLs up to date when the defaults change.
- The SQLite database is stored in `data/agentflow` (mounted into the backend
  container).
- `docker-compose.hermes.yml` is generated by `manage.sh` and is gitignored.
